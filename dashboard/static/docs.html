VeriSync Docs

Everything you need to get reviews running, understand the output, and tune the system for your codebase.

What is VeriSync?

VeriSync automatically reviews every PR and push to main. It splits each diff into chunks, routes each chunk to the cheapest AI model that can handle it, and posts verified findings as inline GitHub comments — all without you doing anything.

The key difference from other AI review tools: every AI call costs real Bitcoin sats. The cost appears in your dashboard, attributed to the exact model, file, and finding that generated it. Nothing is hidden in an opaque subscription.

⚡

Economic accountability

Every finding has a price tag, a model behind it, and a Lightning transaction receipt.

🧠

Intelligent routing

The RL router learns your codebase and sends expensive models only where they're needed.

🛡️

Verified findings

A verifier agent checks every finding before it reaches you. No false-positive noise.

🔗

Zero-friction

Registers GitHub webhooks automatically. Push code, get reviewed. No buttons to press.

Quickstart

1. Clone and install

git clone https://github.com/your-org/verisync && cd verisync
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

2. Create a GitHub OAuth App

Go to GitHub → Settings → Developer settings → OAuth Apps → New OAuth App.

  • Homepage URL: http://localhost:8000
  • Callback URL: http://localhost:8000/auth/callback
  • Required scopes: repo, read:user, admin:repo_hook

3. Fill in .env

GITHUB_CLIENT_ID=your_client_id
GITHUB_CLIENT_SECRET=your_client_secret
GITHUB_REDIRECT_URI=http://localhost:8000/auth/callback
SESSION_SECRET_KEY=   # python -c "import secrets; print(secrets.token_hex(32))"
ANTHROPIC_API_KEY=sk-ant-...  # only if using Claude models
WEBHOOK_URL=https://xxxx.ngrok.io/webhook/github  # public URL for GitHub

4. Pull models and start

ollama pull llama3:8b && ollama pull mistral:7b  # optional local models
python -m router.seed      # seed RL router with training data
uvicorn main:app --reload  # start on :8000
💡 For local development
Use ngrok http 8000 to get a public URL for webhook delivery, then set that as WEBHOOK_URL.

Connecting repos

After signing in, you'll see a Watch a repo… dropdown in the top nav. Select any repo — VeriSync immediately registers a webhook on it via the GitHub API.

1

Select a repo

Click the dropdown in the nav bar and choose a repo. You'll see a confirmation toast.

2

Webhook registered

VeriSync calls the GitHub API to create a push + pull_request webhook targeting your public URL.

3

Push to trigger

Open a PR or push directly to main. The review starts within seconds — watch the live feed on the Dashboard.

ℹ️ What triggers a review
Pull requests opened or updated targeting main, and direct pushes to main. All other branches and events are silently ignored.

The live feed shows every step of a review as it happens. Events arrive over SSE (Server-Sent Events) and are automatically reconnected if the connection drops.

Understanding findings

Findings are posted as inline PR review comments on GitHub, one per issue. Each comment includes the model that found it, the confidence score, the suggested fix, and the cost.

Severity levels

SeverityMeaning
critical 🔴Security vulnerabilities, data loss risks, or broken logic that must be fixed before merging.
warning ⚠️Code quality issues, performance problems, or logic edge cases worth addressing.
info 🔵Style suggestions, naming conventions, or test coverage notes. Nice-to-have.

The verifier

Every finding passes through a verifier agent (Gemini Flash) that checks two things: Is this issue real? and Is the suggestion actionable? Findings that don't pass verification are discarded before reaching GitHub. This is why the "Verifier pass" stat matters — a lower pass rate means the reviewer model is producing lower-quality findings and may need replacing in the registry.

Tracking spend

VeriSync uses USE_MOCK_WALLET=true by default — all sats are in-memory and reset on restart. This is fine for development. When you're ready to use real Lightning payments, set USE_MOCK_WALLET=false and configure your MDK wallet.

The Cost by model chart on the dashboard shows exactly how your budget is being used. If a single model dominates, check whether the RL router has been seeded with enough episodes — run python -m router.seed to add 80 synthetic training examples.

⚠️ Budget tip
Security chunks routed to claude-sonnet (150 sats) dominate cost. If you're on a tight budget, lower the cost_sats threshold for escalation or remove expensive models from registry.yaml.

Pipeline stages

Each PR diff is split into per-hunk chunks. All chunks for a PR process concurrently. Visit the Pipeline page to watch nodes light up live.

01

Classifier llama3:8b · 5 sats

Tags each chunk as style, logic, security, architecture, or test-coverage. Always runs first — this tag drives the router's prediction.

02

Router RL model · 0 sats

Uses the classifier tag, file extension, and diff size to predict the cheapest model tier likely to produce a verified finding. Falls back to tier 0 if not enough training data.

03

Reviewer Tier 0–5 · 5–150 sats/chunk

Calls the worker endpoint for the selected model. Returns a list of findings: issue description, line number, severity, and suggested fix.

04

Verifier Gemini Flash · 40 sats

Validates each finding. Sets verifier_accepted=true and writes an episode to SQLite. If rejected and budget allows, escalates to the next tier.

05

Escalate — sats

If the verifier rejects findings and retry_count < max_retries, bumps to the next model tier and re-runs from the Reviewer. Max 2 retries per chunk.

06

Synthesiser Gemini Flash · flat fee

Runs once per PR after all chunks complete. Groups and deduplicates findings, generates the summary comment, and posts everything to the GitHub PR.

Model registry

The registry is a YAML file (registry.yaml) at the project root. On startup, VeriSync reads it and registers one worker endpoint per model. Add a model, restart the server — done.

models:
  - id: llama3-8b          # used in URLs and logs
    name: "llama3:8b"      # passed to the provider API
    provider: ollama       # "ollama" | "anthropic"
    cost_sats: 5           # deducted per chunk
    endpoint_url: "http://localhost:8000/worker/llama3-8b"
    capability_tags: ["style", "classify"]

  - id: claude-sonnet
    name: "claude-sonnet-4-5"
    provider: anthropic
    cost_sats: 150
    endpoint_url: "http://localhost:8000/worker/claude-sonnet"
    capability_tags: ["security", "architecture", "logic"]
ℹ️ Adding a custom model
Add an entry to registry.yaml, set provider: ollama and pull the model locally (ollama pull your-model), then restart the server. The new worker endpoint appears automatically and the router will start routing to it.

Capability tags

Tags are hints for the router — they indicate what this model is good at. The router uses them alongside classifier output and historical episode data to make predictions.

TagUse for
styleFormatting, naming, dead code, comment quality
logicAlgorithm correctness, edge cases, null handling
securityInjection, XSS, auth bypass, hardcoded secrets
architectureCoupling, God objects, circular dependencies
test-coverageMissing tests, untested branches
classifyModels also suitable for the Classifier stage

RL Router

The router predicts the cheapest model tier that will produce a verified finding for a given chunk. It uses a OneVsRest logistic classifier with these features:

  • Sentence embedding of the diff text (384 dimensions, all-MiniLM-L6-v2)
  • One-hot encoding of the classifier tag
  • Log of cost_sats per tier

The router retrains every 10 new episodes. On first run (no history), it defaults to tier 0 (cheapest model).

Seeding the router

Run this once before demo to generate synthetic training data across all tiers:

python -m router.seed

This inserts 80 episodes into the SQLite database with realistic tag/tier/outcome distributions. The router will train immediately on the next request.

Cost model

Each worker call deducts cost_sats from the user's wallet. Costs are per chunk (one hunk of one file), not per PR. A typical PR with 10 chunks costs 50–300 sats depending on what the router selects.

Webhooks

VeriSync registers push and pull_request webhooks automatically when you select a repo. The webhook secret is generated per-repo and stored in SQLite — it's used to verify X-Hub-Signature-256 on every incoming request.

Local development

ngrok http 8000
# Copy the https URL, e.g. https://abc123.ngrok.io
# Set WEBHOOK_URL=https://abc123.ngrok.io/webhook/github in .env
# Restart the server
⚠️ ngrok URL changes on restart
If you restart ngrok, you get a new URL. Re-register the webhook by unwatching and re-watching the repo from the dashboard dropdown, or update the webhook URL directly in GitHub Settings → Webhooks.
